# macOS performance pass — September 8–9, 2026

Validation status: performance changes implemented; **automated gates remain
unmet**. Release was held at the end of this investigation. On September 9 the
user subsequently explicitly authorized "push and release" for v0.14.4 with
the documented caveats; that decision does not turn failed measurements into
passes or establish a successful manual validation run.
Early renderer measurements ran while the desktop was locked. After the user
enabled UI automation, the runner successfully launched and interacted with the
app. The latest real-copy confirmation misses the frame gate at 34.773 ms.
Real-copy menu checks led to lazy rows and bounded config reads, but Graph draws
still reach 172.169 ms. The latest 493-test serial run also fails one unchanged
model-assessment assertion. No version/tag/release was published during this pass;
scene-update measurements are not proof of display presentation or responsiveness.

The user's requested additional pass is recorded in the
[September 9 follow-up](2026-09-09-follow-up.md), including the particle on/off/on
comparison, menu phase attribution, and local 0.14.4 validation build. That pass
does not waive the failures recorded here.

## Method

- Apple M4 Max, 64 GiB RAM; macOS 26.6.2; Xcode 26.5 / Swift 6.3.2.
- Release builds with pinned dependencies and the actual compiled Metal shaders.
- Baseline: `185e656`, with only the isolated/deterministic measurement harness
  applied. Candidate: the performance branch based on that revision.
- Seed 42, deterministic hashing, target-azimuth orbit at 20 degrees/second.
  Synthetic runs record 1,800 frames and discard 1,000 active warmup frames.
  Real-copy orbit runs record 3,600 frames and discard 1,500 active warmup frames.
- Baseline and candidate timing runs were serial, with no competing compiler or
  other Engram benchmark. App Nap was disabled only for the measured children.
  Other desktop applications were not closed. A process check after the final
  run showed an Android emulator, Figma, and WindowServer active; no thermal
  warning was reported. This was not a fully controlled idle desktop.
- Final confirmation runs used clean child environments. Changing desktop/
  compositor conditions and the surrounding workload limit frame-cadence
  comparisons. The September 9 unlocked retry had only the benchmark-owned
  Engram process active and no overlapping compiler, UI test, or model test.
- The real fixture is a read-only SQLite backup: 31,674 memories and 159,730
  graph edges with both endpoints present. Only the disposable copy is mutated.
  Account/sync/updater startup is disabled, copied filters are cleared, layout is
  Force, and sound/notifications are off. Mascot rendering is preserved.
- Loaded/LOD-selected edges are not simultaneous draws. Both revisions retain
  the existing macOS 26 instance-texture limit of 16,384 actual edge instances.

See [the reproducible procedure](macos.md) for commands, measurement boundaries,
and release gates. Raw database copies, screenshots, and logs remain local.

Earlier candidates measured 12.560 ms in the close 40,000-node orbit and
23.254 ms in the real-copy orbit (`final2-40k-close` / `candidate-real-orbit3`).
The table deliberately uses the latest results, not the best runs. The
frame-cadence variation cannot be confidently attributed to Engram versus the
desktop/compositor conditions. The previous real-copy confirmation measured
34.514 ms (`confirm-real-orbit`); the unlocked retry measured 33.898 ms and
still fails. Its warmed scene CPU maximum was 8.093 ms.

In the unlocked retry, 85.7% of update intervals were within 1 ms of either
16.667 or 33.333 ms. Their correlation with measured same-frame scene CPU was
-0.078 (preceding-frame CPU: 0.049). This identifies a cadence pattern, not its
cause: the CSV records RealityKit update deltas, not presented-frame timestamps,
GPU duration, or intervening main-thread work. A separate diagnostic confirmed
an onscreen 900 × 632-point window at 2× scale on the external 60 Hz display.
That geometry was not recorded continuously for the earlier comparisons.

A 30-second attached Metal System Trace was stopped during post-processing:
Instruments continued consuming a CPU core for several minutes and its own
sample reported a 75.4 G peak footprint. A 6.75 GB raw Apple trace stream
survived, but no finalized analysis tables were produced. The interrupted
capture does not establish an Engram bottleneck. Its diagnostic app completed
the requested 120-second run; neither that run nor UI work overlapping trace
processing is quiet performance-gate evidence. Raw artifacts remain local.

A subsequent bounded five-second Time Profiler capture completed and exported
normally (`cpu-trace-bounded`). Its 5.685-second recording contains 2,115 ms of
main-thread running sample weight: 1,478 ms includes Engram's scene update,
while 611 ms includes RealityKit display-link work outside that callback.
A separate Render thread has 3,370 ms of running samples, including 2,750 ms
under VFX simulation (81.6%). Nebula emitters are the renderer's only
`ParticleEmitterComponent` construction; this identifies a useful investigation
candidate outside `total_ms`, not proof of which emitter or whether invisible
particles are simulated. `StableInstanceSlots.update` also has 720 ms of
inclusive main-thread sample weight, largely UUID collection/hash operations.
Running CPU samples do not measure waits, GPU duration, or presentation and
cannot establish the cause of the 33.898 ms cadence result.

The first index-cache experiment used several additional hash tables and was
rejected after an isolated Release benchmark: 8,000-node reorder improved only
about 1.5%, while 1% node churn and both 30,000-edge cases became slower. Its
topology-changing fallback roughly doubled in cost (nodes 740→1,312 µs;
edges 2,475→4,601 µs). Passing its seven correctness tests did not justify
keeping a slower implementation (`slots-index-benchmark-initial.csv`).

A bounded dense-array alternative with lazy initialization passed eight
isolated Release tests, including randomized slot invariants and sparse-index
fallback. Repeated microbenchmarks show 2.36–2.64× faster warmed slot updates:
8,000-node reorder/churn p50 is 278/305 µs versus 716/719 µs; 30,000-edge input
with 16,384 slots is 897/979 µs versus 2,369/2,387 µs. Topology-changing fallback
is about 2.5% slower (tens of microseconds). The first lazy-cache update is also
faster than the old reconciler, and all initial reconciliations are at most
4.213 ms (`slots-index-benchmark-dense-cold.csv`). This candidate is retained for
integrated checks, not assumed to satisfy the frame gate from a microbenchmark.

The baseline real-copy process completed normally with 3,599 recorded frames;
the original harness incorrectly checked completion against only nonempty
post-warmup frames. The saved CSV was revalidated and analyzed after fixing that
completion check (`baseline-real-orbit-analysis.json`).

## Final ordinary Release renderer confirmation

The final candidate includes the dense slot cache, lazy sidebar, visibility
lifecycle, and per-render config snapshot. It was built without testability
flags, staged with current shaders, and measured after UI automation finished.
The real-copy orbit (`config-snapshot-real-orbit`) records 3,599 frames in
98.660 seconds and analyzes 1,866 warmed active frames. Frame interval p95 is
**34.773 ms, failing the 33 ms gate**. Scene CPU p95 is 5.223 ms, warmed maximum
5.761 ms, and cold-inclusive maximum 75.963 ms. All 31,674 nodes and 159,730
graph edges are retained. Lower scene CPU work does not clear the frame gate;
the preceding 33.898 ms result and earlier passing measurements remain in the
report and are not substituted for this latest failure.

Window metadata captured during this run confirms an onscreen 900 × 632-point
window at 2× scale on the external 60 Hz display, matching the prior diagnostic.
This is update-cadence evidence, not GPU/presentation timing or an established
cause of the misses.

All six final synthetic renderer cases pass both the warmed frame and
cold-inclusive scene CPU budgets. Each records 1,799 frames with the same
1,000-active-frame warmup, loaded graph, camera scale, seed, and drawing budgets.
Artifacts are `config-snapshot-4000-*` and `config-snapshot-40000-*`.
